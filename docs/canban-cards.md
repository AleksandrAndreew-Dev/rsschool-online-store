## Карточки

### KAN-01 | Создать GitHub Project и доску Kanban

- **Владелец:** Dev 1
- **Начальная колонка:** To Do
- **Описание:** Создать проект на GitHub, настроить доску в представлении **Board**, добавить колонки `To Do`, `In Progress`, `In Review`, `Done`. Пригласить напарника с правами редактирования доски.
- **Приёмка:** Доска доступна обоим участникам, колонки созданы, ссылка на доску привязана к репозиторию.
- **Зависимости:** —

### KAN-02 | Настроить базовый роутер SPA

- **Владелец:** Dev 2
- **Начальная колонка:** To Do
- **Описание:** Реализовать клиентский роутер для SPA без перезагрузки страницы (используя History API или Hash). Настроить роутинг для путей `/` (или `/catalog`), `/cart` и `/about`. Экспортировать функции `initRouter()`, `navigate(path: string)` и механизм подписки на смену маршрута (`onRouteChange(callback)`), чтобы общая оболочка могла переключать отображаемый контент.
- **Приёмка:** Переходы между страницами работают корректно при клике на ссылки и кнопках «Назад/Вперед» в браузере; URL в строке адреса обновляется.
- **Зависимости:** —

### KAN-03 | Создать общую оболочку приложения

- **Владелец:** Dev 2
- **Начальная колонка:** To Do
- **Описание:** Создать корневой HTML/TS-шаблон приложения, включающий стационарные блоки: `Header` (шапка с навигационными ссылками на каталог, корзину и «О нас», а также счётчиком товаров в корзине) и `Footer` (подвал). Предусмотреть контейнер-outlet (`renderOutlet(component)`) для динамической подстановки страниц роутером.
- **Приёмка:** Шапка и подвал отрисовываются на всех экранах; при переходе по роутеру меняется только содержимое outlet-контейнера; счётчик товаров в шапке доступен для обновления извне.
- **Зависимости:** KAN-02

### KAN-04 | Наполнить каталог товарами

- **Владелец:** Dev 1
- **Начальная колонка:** To Do
- **Описание:** Создать файл `src/data/products.ts` и экспортировать массив данных (минимум 8–12 товаров медицинской/аптечной тематики, не менее 2 категорий). Описать TypeScript-интерфейс `Product` с обязательными полями: `id` (string/number), `title` (string), `category` (string), `price` (number), и опциональными: `image` (string), `description` (string).
- **Приёмка:** Массив содержит не менее 8 валидных объектов товаров из разных категорий; тип `Product` строго соблюдается.
- **Зависимости:** —

### KAN-05 | Компонент карточки товара `ProductCard`

- **Владелец:** Dev 1
- **Начальная колонка:** To Do
- **Описание:** Разработать изолированный UI-компонент `ProductCard(product: Product, onAdd: (product: Product) => void)`. Компонент должен отображать название, категорию, цену, изображение (с fallback-заглушкой при его отсутствии) и кнопку «В корзину». Внутри компонента **не должно быть** логики работы с хранилищем корзины — только вызов переданного колбэка `onAdd`.
- **Приёмка:** Карточка корректно рендерит переданные данные; клик по кнопке «В корзину» триггерит колбэк `onAdd` с правильным объектом товара в качестве аргумента.
- **Зависимости:** KAN-04

- **Приёмка:** На странице отображается полный список товаров; клик по кнопке добавления на любой карточке успешно передает товар в систему корзины.

### KAN-17 | Промокод `SALE10`

- **Владелец:** Dev 2
